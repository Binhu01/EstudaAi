# Steve — backend e autenticação — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Entregar autenticação por e-mail e endpoint de IA contextual com cotas atômicas e falhas seguras.

**Architecture:** Adaptadores Firebase REST e OpenAI Responses usam fetch HTTPS do Node, com Firebase Admin verificando identidade. Quotas são reservadas em transações PostgreSQL curtas; transporte externo fica fora delas. Rotas e DTOs ficam em módulos próprios, registrados pelo createApp existente.

**Tech Stack:** NestJS/Swagger/class-validator/Throttler existentes, Prisma/PostgreSQL, Node 24 fetch, Firebase Admin, PGlite para SQL e PostgreSQL real para concorrência.

**Spec:** [Especificação](../specs/2026-09-30-experiencia-estudo-design.md), [contratos globais](2026-09-30-experiencia-estudo.md).

## Global Constraints

Todas as restrições do índice. Auth IP 10/min para cadastro/login/reset, 60/min refresh separado. ID token verificado pelo Admin antes da resposta; nunca logar corpos/credenciais. Steve privado, papéis user/assistant, mensagem até 2.000 e histórico até oito/12.000 caracteres. Cota diária UTC 10/usuário e 1.000/global; 3/min/usuário e uma simultânea/instância. Provedor 30s, 800 tokens, store=false; sem retries automáticos ou refund de envio incerto.

## Review Focus

Rotas públicas não podem desativar quota IP nem dereferenciar user ausente. Key REST de outro projeto não retorna sessão. Última vaga, falha intermediária, liberação repetida/meia-noite e reinício preservam quotas. Payload de sistema ou catálogo inválido não chega ao modelo; respostas vazias/refusals/incomplete não parecem resposta concluída.
